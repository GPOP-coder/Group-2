# Pete's Unifocus Manager (Basic) Training Curriculum

**Status:** Living document — first captured 8/4/26, sourced from Pete's own long-standing facilitator outline ("Unifocus - Manager Training Guide," Unifocus-branded, generic quick-reference video links). This is the **operational/usage tier** — the counterpart to [08-admin-training-curriculum.md](08-admin-training-curriculum.md)'s config/admin tier. Same relationship as that document: this is Pete's own reusable IP, not client-specific — update after every delivery rather than rebuilding from scratch.

**Cross-client terminology:** Mohonk calls this "Basic Training"; HM Alpha calls it "manager days" (New Orleans/Nashville format: 1 admin day + 2 manager days, 13 managers). Same curriculum skeleton, tailored per client each time — see [08-admin-training-curriculum.md](08-admin-training-curriculum.md)'s "Two-tier training model" note for the full cross-client mapping.

**Audience:** Department managers/supervisors who need to *use* the system day-to-day — scheduling, employee maintenance, running reports — not the property's designated admin/champion (that's the admin tier).

## Curriculum Outline (source: facilitator guide, 2-page table format)

| Subject / Topic | Facilitator Key Points — Tips — Ideas |
|---|---|
| **Navigation** ([portal.unifocus.com](https://www.portal.unifocus.com)) | Make sure all users can log in · User profile · Help Section (Videos, Portal, and Open Uni Sessions) · Unifocus main menu |
| **Planning Menu** ([video](https://www.unifocus.com/vid/qrv-fp-rms10)) | LMS Timeline · Environments · Forecast (Rooms, Banquets, F&B and other Revenue Centers) · Project Hours and Generate Schedules · Manage/Publish Schedules |
| **Scheduling** ([video](https://www.unifocus.com/vid/qrv-sch-rms10)) | Main navigation buttons — Changing the Week, Sort Functions, Filter Jobs, View Options (Hide Unscheduled Secondary Jobs), Show Daily Summary (Scheduled vs. Projected Hours), Show KBI Data (current forecast), Save View · Edit Shifts — Create/Edit Shifts, Copy/Paste Shifts, Drag and Drop Shifts, Explain Icons and Labels · Delete, Restore, and Copy Schedules · Manage/Publish and Print Schedules · **Distribution logic customization (balanced / hardest-day-first / busiest-day-first / modified peak / seniority) — most relevant for larger departments, roughly 40+ people (added 8/6/26). Real live example worth reusing: a manager asked why a genuine staffing shortfall concentrated entirely on Friday–Sunday while Monday–Thursday looked fully staffed — answer: shift-making (how many, volume-driven) and shift-filling (who gets them) are separate, and filling defaults to left-to-right across the week, so an under-staffed department's gap lands wherever the week runs out, typically the weekend. "Balanced Schedules" distribution spreads the shortfall evenly instead.** · **Gotcha: new hires don't auto-join schedule groups and can silently vanish from filtered views/printouts unless added manually (added 8/6/26)** |
| **Employee Maintenance** ([video](https://www.unifocus.com/vid/qrv-em-rms10)) | Regular Schedules (Variable/Regular/Permanent) · Availability — **the primary lever to "rein in" the auto-scheduler; managers can still manually override outside a set window (added 8/6/26)** · **"Thermometer" indicator — visual hours-used-vs-available gauge, source of overtime warnings, overridable with authority (added 8/6/26)** · Scheduling Groups · Assignments · Secondary Job Codes · Sub Only feature — **confirmed the practical center of gravity of this whole tier across two separate deliveries (8/4 and 8/6) regardless of department mix; budget accordingly** |
| **Employee Request** ([video](https://www.unifocus.com/vid/qrv-ta-rms10)) | Create Time Off Requests · Approve Requests · **Where time off is ADP-driven (Mohonk's case): teach the ADP↔Unifocus sync behavior instead of the native screens — approved before Generate Projected Hours runs = honored automatically; approved after = shows as a blue line requiring manual resolution (added 8/6/26)** |
| **Actuals** | Enter Actual KBIs · Generate Standard Hours · Enter Actual Hours (Contract Labor) — **increasingly looks more theoretical than hands-on for Mohonk managers across two deliveries now; usually folds implicitly into the Reports discussion (actual vs. standard) instead of being taught as its own data-entry module — worth a deliberate decision on whether to keep as a standalone outline row** |
| **Reports/Dashboard** ([video](https://www.unifocus.com/vid/qrv-repter-rms10)) | Labor Effectiveness · Weekly Labor Summary — **read bottom-up, Actual vs. Standard is the core metric, target ±5%; consistent, repeatable teaching pattern across every Mohonk delivery captured so far, not session-specific** · File Types (PDF, Excel, CSV, etc.) · Schedule Reports · Labor Dashboard · **Daily Labor Report and the 7-week historical trend view, taught as explicit named tools (added 8/6/26)** · **"Shield, not sword" — the definitive verbatim version, worth using exactly (confirmed live 8/6/26): "This is a shield. I want you to look at this like a shield, it's not a sword." The point isn't defending the number as perfectly precise — it's giving a manager something concrete to point to when justifying variance ("here's what I should have needed, and here's specifically why I needed more") instead of litigating every disruption in the abstract. Explicitly used to isolate genuinely quantifiable one-off disruptions (a pipe break, an illness cleanup, training, a real staffing shortfall) as named exceptions rather than burying them inside vague, unexplained variance.** |

## Delivery Log

### 8/4/26 — Mohonk (Security & Call Center), tailored, compressed to ~2 hrs
First captured field test against this framework. Full session notes: [2026-08-04_basic-training-security-callcenter.md](../clients/mohonk/2026-08-04_basic-training-security-callcenter.md).

**Coverage vs. outline:**
- **Navigation** — covered as designed (help menu, PDF handbook, online help, quick-reference videos, support ticket path).
- **Planning Menu** — covered conceptually (weekly rhythm: forecast Mon → generate projected hours Tue 3pm → generate schedules Wed 2am → draft ready Thu → publish Fri), not a deep forecast-screen walkthrough — both Security and Call Center run **fixed standards**, so live forecasting mechanics weren't the point for this room.
- **Scheduling** — covered: filter-by-job, Delete/Restore/Copy habit directly addressed (Molly had been blowing up her schedule most weeks — this is the exact behavior the curriculum's "Delete, Restore, and Copy Schedules" line is meant to head off). Scheduling Groups noted as unused by Security, not built out live.
- **Employee Maintenance — the actual center of gravity this delivery**, well beyond its outline weight: Regular Schedules (Variable/Regular/Permanent modes taught with real examples), Availability (Required Off + Available to Work built live for Carol Carroll and Kevin Messer), Secondary Job Codes (the Carol Carroll cross-department gap found live — see session file), Assignments (Call Center's un-standardized task assignments explained as the reason for their external Excel/macro workaround), **Sub Only feature** (taught live via Carol Carroll's existing F&B secondary jobs — Buffet Attendant/Server Assistant, already correctly set by James to prevent unwanted auto-scheduling — generalized to Security officers with secondary jobs elsewhere). Full outline module list covered.
- **Employee Request** — **not covered.** Mohonk's time-off flow runs through ADP, not Unifocus's own request/approve screens — consistent with the property-wide pattern already documented, but this outline module was skipped rather than adapted.
- **Actuals** — **not covered** as its own module; folded implicitly into the Reports discussion (actual-vs-standard) rather than taught as data-entry mechanics. Reasonable for two fixed-standard departments with no volume-driven actuals to enter.
- **Reports/Dashboard** — covered, and covered live/hands-on rather than just walked through: Weekly Labor Summary and Weekly Projected Schedule reports run against real Gatehouse/Security/Call Center data (see session file for the actual numbers). Labor Dashboard **not** retested here — already flagged broken in the 8/3 admin session, not re-attempted with this room.

**Takeaway for the next delivery:** the outline holds up well as a checklist, but real sessions skew hard toward whatever the room's actual pain points are (Employee Maintenance ate most of the clock here) — budget accordingly rather than trying to hit every module evenly, and explicitly decide up front which modules to cut if time is tight (this delivery implicitly cut Employee Request and Actuals; worth deciding that on purpose next time rather than by clock pressure alone).

### 8/6/26 — Mohonk (Housekeeping, Kitchen, Recreation), full-length, 3h07m
Second field test against this framework — the largest, longest, most cross-departmental delivery yet, mixing rooms with zero prior Unifocus exposure with rooms already scheduling in Excel or other systems. **Full verbatim transcript reviewed 8/16/26**, extending well past the AI notes: [2026-08-06_basic-training-housekeeping-kitchen-recreation.md](../clients/mohonk/2026-08-06_basic-training-housekeeping-kitchen-recreation.md). **Two more repeatable Pete quotes confirmed live, worth using verbatim:** "Unifocus to me is like a big 'compared to what' machine" (the whole system's purpose in one line), and a direct, unprompted confirmation of the hours-first philosophy — "we haven't talked about any dollars or pay or revenue... we almost care about it zero. If you get your hours right, the dollars will follow." Also independently confirms this session's own KBI/KPI terminology correction: asked live what "KBI" means, Pete's own answer was "it's not a KPI, which is like a performance indicator... the KBI, key business indicator, is the volumes" — and the EcoLab Training explainable-variance example recurred here too, confirming it as one of Pete's real, reusable go-to illustrations rather than a one-off.

**Coverage vs. outline:**
- **Navigation** — not separately called out in the AI summary; likely covered briefly as scene-setting, not a focus.
- **Planning Menu** — covered as the backbone of the whole session: the full Monday→Friday weekly cycle (forecast entry → Generate Projected Hours/Schedules → manager edit window → labor meeting → publish) taught as one continuous narrative rather than a menu-by-menu walkthrough. Manage Schedules explicitly taught as its own tool (completion status, projected-vs-scheduled variance, complete/approve/publish workflow) — this curriculum's outline currently only lists it as a single bullet under Planning Menu; this delivery gave it real independent weight, worth reflecting in the outline.
- **Scheduling** — covered in real depth: Open Shifts drag-and-drop, icon meanings, auto-break-insert threshold (5.5 hrs), and a **genuinely new-to-this-curriculum finding on filters**: new hires don't auto-join schedule groups and can silently vanish from filtered views/printouts unless manually added — a concrete gotcha worth adding to the outline's Scheduling row. Distribution-logic customization (balanced / peak-first / modified peak / seniority) also taught explicitly, framed as most relevant to larger departments — not previously documented in this curriculum file at all.
- **Employee Maintenance** — again a center of gravity, consistent with the 8/4 delivery: Regular Schedules (Variable/Regular/Permanent), Availability strongly framed as *the* lever to "rein in the auto-scheduler," Assignments, Secondary Job Codes, and Sub Only all covered. **New framing worth folding into the outline itself:** the "thermometer" hours-used-vs-available indicator as a specific visual teaching aid for overtime warnings, and availability windows described as something managers set but can still manually override — worth stating explicitly that override capability exists, so managers don't think the availability window is a hard wall.
- **Employee Request** — covered this time (unlike 8/4's Security/Call Center delivery, which skipped it because Mohonk's time-off flow runs through ADP): taught here as *understanding* the ADP sync behavior (approved-before-generation = automatic; approved-after = a blue line requiring manual resolution) rather than teaching Unifocus's own request/approve screens directly — a reasonable adaptation given the ADP-first reality, but worth naming explicitly as the adapted version of this module rather than leaving it ambiguous whether it was "covered" or "skipped."
- **Actuals** — not clearly called out as its own data-entry module here either, similar to 8/4 — folded into the Reporting/Labor Standards discussion instead (actual vs. standard, ±5% target). Increasingly looks like this outline module may be more theoretical than something Mohonk managers actually touch directly — worth a decision on whether to keep it as a standalone outline row going forward.
- **Reports/Dashboard** — covered thoroughly, with a clear teaching frame worth capturing verbatim in the outline itself: **reports as "a shield" for data-driven accountability, not a tool for day-by-day micromanagement.** Weekly Labor Summary again taught as read-bottom-up, ±5% target — consistent with every other Mohonk delivery this KB has captured; this is clearly Pete's standard, repeatable teaching pattern for this report, not session-specific. Daily Labor Report and the 7-week historical trend view were both taught as explicit named tools here, more than in the 8/4 delivery.

**Takeaway for this delivery:** several genuinely new teaching elements surfaced that aren't yet reflected in the outline table itself — the schedule-groups new-hire gotcha, distribution-logic customization, the "thermometer" visual, and the "reports as a shield" framing chief among them. Given two deliveries now both reinforce Employee Maintenance/Availability as the practical center of gravity regardless of department mix, consider promoting it to explicit top billing in the outline rather than leaving it as one row among seven.
